# Navigation regressions

From `web/`:

```sh
npm ci
npx playwright install chromium
npm test
npm run lint
npm run test:e2e
```

Playwright starts an isolated Vite server (`web/e2e/base-url.mjs`) and never reuses one already running on the port, so a run can't silently reuse — and test against — another worktree's server. Locally it picks a free port automatically unless `E2E_PORT` is set; set `E2E_PORT` explicitly to run the suite in more than one worktree at once (each needs a different value). CI always uses the default port, 5198, since it only ever runs one job at a time. Fixtures use the real router and, where appropriate, real Library/Detail/Person components with mocked TMDB data; no pairing or personal credentials are needed. Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` only to use an existing compatible Chromium installation.

TV preview diagnostics for [#746](https://github.com/oxyc/den-edge/issues/746) are retained in `test-results-tv/preview-<platform>-<port>-<engine>.jsonl`, beside the browser traces in the existing `tv-failures` / `tv-native-failures` CI artifacts. The Playwright TV config enables them only for the isolated test preview. They do not run in normal builds or developer previews. To investigate the original journey locally, run `DEN_TV_TEST_ENGINE=webkit npm run test:e2e:tv -- tv-library-stress.spec.mjs --grep '24-title normal'`.

Compare the trace's request wall-clock time with the JSONL `at` timestamps. `request` means Vite received the HTTP request, `finish` means Node finished writing its response, and `close` without `finish` means the connection ended early. Only the method and known navigation/static path identities are recorded; other paths (including capability-bearing addon, media, invite and recovery URLs) become `/[redacted]`. Headers, bodies, query strings and fragments are omitted. Mocked Playwright responses never reach this logger and cannot prove server health. A received request without completion is listed by ID and age in each one-second `sample`; other completed requests show whether the server is still serving. A trace request absent from an otherwise live server log points to the browser/transport before server receipt, while a logged `finish` locates the remaining wait after the server wrote its response. Neither alone establishes the root cause.

Samples include preview-process CPU, RSS, event-loop utilization and maximum delay, plus runner load and free memory. A gap in samples or a large `elapsedMs` can expose a blocked or stopped preview process; resource values help interpret it. A diagnostic filesystem failure emits a generic warning and disables logging while preview serving continues, so missing logs after that warning are not evidence of a server stall. Each invocation replaces its log and caps it at 8 MiB plus a final `truncated` marker: no absence after that marker is evidence. Save the exact commit, run attempt, engine and worker count along with this evidence. This instrumentation does not resolve the original intermittent stall; keep retries, navigation timeouts and production worker supervision unchanged until the cause is demonstrated.

Coverage includes nested Back/Forward, scroll and horizontal rails, search/form state, retained rows, repeated visits, reduced motion, missing View Transition support, rapid navigation, swipe cancellation/overlap, ghost clicks, interior versus carousel gestures, loading covers, the Home → movie 1 → Home → movie 2 wrong-snapshot regression, direct hash entries, independent snapshot DOM ownership, frozen animation geometry, movie → actor → Back, poster rendering, and delayed metadata/image layout stability. Unit tests cover gesture direction/ownership and cancellation during asynchronous landing.

Synthetic touch events exercise the app's handlers. They cannot reproduce native Brave/iPhone gesture arbitration, memory pressure, or rotation behavior; physical-device testing remains necessary.

Actor landing coverage independently delays filmography, completes it while the page is hidden, and compares frozen/live screenshots at the actual handoff. It repeats Forward in portrait and landscape, including a saved bottom scroll that must clamp after rotation. Branch tests verify exact movie IDs, and separate visits to one movie retain independent form/scroll state. Discarded history branches are released.

Billboard viewport tests keep the hero and following content fixed during height-only touch viewport changes, while checking that rotation and desktop resizing still respond. See [NAVIGATION_AUDIT.md](NAVIGATION_AUDIT.md) for reviewed behavior and remaining limitations.

Billboard loading tests delay metadata and artwork independently, check title/metadata/overview/action rectangles, and compare short/long-title slides. Desktop navbar coverage checks scoped Back, keyboard activation, direct-link fallback, the existing Den icon, and 320px/390px layouts.

Detail trailer tests play a generated, silent WebM through mocked byte-range responses. They check detail playback starting at zero seconds, muted single playback, mobile media above the details, desktop overlay layout, unchanged geometry after playback starts, pause/resume offscreen, missing/broken trailers, blocked autoplay, reduced motion changes, late resolution after leaving a route, and frozen video pixels in independently displayed swipe snapshots.

Mobile trailer regressions suppress compositor callbacks while real video plays and compare screenshot pixels for opaque letterboxing, both live and in a swipe snapshot. YouTube link tests cover the visible Trailer label, exact videos and search fallback, mobile handoff links, desktop new tabs, and the full action row at 320px.

Navbar search has its own retained SPA route. Tests cover mobile expansion and Cancel, direct-link fallback, immediate cancellation during a transition, keyboard focus, stale-query responses, and Home/result scroll restoration. Settings keeps its word on a laptop and shows only its sliders mark below 760px, where the word is hidden visually rather than removed — so its accessible name is the same at every width and the tests still find it by that name. The Home tab is hidden below 760px too, because the mark beside it links to the same page. Navigation regressions use their own fixture nav rather than this bar, so they are unaffected by either.

Mobile billboards open details by tapping the slide, with native horizontal swipe and independent pagination dots. Action buttons remain on desktop. Normal phone widths use one heading line; widths below 360px keep two. Delayed discovery must preserve the visible billboard and its selected slide.

A household the size of a long-lived one lives in `big-library.mjs`: about 1,890 titles, 11,000-odd episode marks and 6,100 rows, generated (the same all day) and moved by the real app into the Owner library of a profile household with its Kid, against the in-memory den-edge of `guest-edge.mjs`, with TMDB answers the size of TMDB's own. Like a real one it has a season downloading and an assistant allowed to change and read it, so every page publishes Owner's lists for it and drains its queue. Use it wherever work per title, row or card could hide behind a three-title fixture: `bigHousehold(context, edge)` once, then `routeBigHousehold(page, edge)` per page. `big-library-budgets.spec.mjs` holds each surface of it — Home, Series, Watchlist, a series' episode list, Settings and the Kid's Home — to a time-to-content budget, its library rows to a `shelves ready` budget, and to how many IndexedDB transactions its library Worker makes and assistant projections it builds or uploads, in WebKit at an iPhone's size and in Chromium at a phone's with its CPU slowed. It runs against the production build, alone: `npm run test:e2e:budgets` (`playwright.budgets.config.ts`), CI's `e2e budgets` job; `npm run test:e2e` leaves it out. To budget a new surface, add it to `SURFACES` there: its path and the `markReady` fields that mean it has drawn.

Title actions show a press at once and save it after (`title-actions-optimistic.spec.mjs`). A fixture library holds and fails writes to check the pending pulse (delayed 150 ms, still under reduced motion) and the rollback with its toast; the production Worker runs against an in-memory den-edge (`library-edge.mjs`) that holds, drops or refuses batch writes, to check the page no longer waits on den-edge, keeps a write it could not send, and takes back one den-edge refuses.
